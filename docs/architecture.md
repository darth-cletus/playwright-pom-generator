# Locator engine architecture

The content script orchestrates a scan of the top-level document. Discovery covers the existing native controls and content-editable elements, plus additional interactive ARIA roles such as switches, tabs, and menu items. Static headings, images, dialogs, and tables are available for role analysis and validation. The scan still focuses on interactive controls.

1. `src/content/accessibility.ts` uses `dom-accessibility-api` for accessible names, implicit role defaults, and accessibility-tree visibility. It handles fallback ARIA roles, input list context, and table header/cell context. Native DOM label associations and ARIA references provide separate label candidates.
2. `src/content/metadata.ts` derives the display label and interaction type. `src/content/candidates.ts` proposes native Playwright strategies and CSS selectors. Canonical strategy and argument keys remove duplicates. A full DOM-order CSS path is added only when other proposals have no unique target match.
3. `src/content/validation.ts` resolves candidates against a scan-local DOM snapshot and caches query results and semantic indexes. The validator takes a structured locator and its intended element. A future validator can supply evidence with the `playwright` method.
4. `src/core/scoring.ts` applies deterministic reliability heuristics. `src/core/python.ts` serializes approved locator arguments into Python calls. The JSON export retains structured data and the chosen candidate ID. The browser never evaluates generated Python.

## Candidate model and ranking

Each candidate has a canonical ID, a discriminated strategy with literal arguments, a basis, a score, explanations, warnings, and validation evidence. Evidence records the method, status, and when available the count and whether the target is among the matches. Current locators are scoped to the scanned document.

Default base scores are 100 for the configured test ID, 95 for alternative test attributes, role and name, or associated labels, 85 for stable IDs, 80 for placeholder or alt text, 75 for title or exact text, 70 for name, 65 for CSS combinations, 40 for classes, 35 for potentially dynamic values, and 5 for structural CSS. The score is a heuristic on a 0–100 scale. The scorer adjusts for configured test attribute priority, instability, selector complexity, long text, validation confidence, and match evidence. Warnings identify structural dependencies and text that may vary by language. Validation status ranks first, then score, then canonical ID. Only a unique target match is eligible for automatic selection or Python generation.

UUIDs, framework-generated IDs, build hashes, CSS-in-JS patterns, and long opaque identifiers earn stability warnings and lower scores. Numbers alone are insufficient evidence. Manual choice is stored as `choice`; `null` means automatic. Version 0.1.0 JSON stored Python expressions and numeric indices. Version 0.2.0 exports structured locators and candidate IDs. The extension has no model import flow.

## Locator strategies and test IDs

The generator supports `get_by_test_id`, `get_by_role` with an exact accessible name, `get_by_label`, `get_by_placeholder`, `get_by_text`, `get_by_alt_text`, `get_by_title`, and CSS `locator`. Strings are escaped as Python literals.

Default recognized attributes are `data-testid`, `data-test-id`, `data-test`, `data-qa`, `data-cy`, and `data-automation-id`. Settings store the priority order and the attribute the user's Playwright project has configured. Only that attribute produces a native test ID call. Generated Python includes a configuration reminder if it uses a nondefault attribute. Preferences are stored in `chrome.storage.local`.

## Validation and privacy

- **Exact DOM CSS** uses `querySelectorAll` in the scanned document.
- **Browser approximation** uses locally indexed roles, names, labels, and exact strings. Test ID matching uses a DOM attribute lookup and assumes the chosen Playwright configuration.
- **Playwright runtime** records evidence produced by the optional Python companion. Integration tests compare fixture candidates to actual locators and exercise generated Python.
- **Unvalidated** describes candidates for which match evidence is unavailable. The result model also distinguishes unique target, ambiguous, no match, wrong target, and validation error.

Browser estimates can differ from Playwright for browser-specific accessibility behavior, deeply nested text, hidden references, malformed ARIA, pseudo-element text, and Playwright's handling of shadow DOM and frames. Locator evidence is a scan-time snapshot. The scanner omits text from editable areas and skips accessible-name sources that can derive from live embedded control values. Author-provided text and attributes can still contain sensitive data. It does not transmit page data or persist it to extension storage.

## Interactive inspection

The side panel opens a direct, top-frame port scoped to the injected document when Chrome provides its document ID. The port owns the inspection session. The panel tracks inactive, starting, active, stopping, and error states. Switching tabs or navigating stops inspection. Closing the panel, port disconnection, and page unload dispose of listeners and highlights. The service worker opens the panel and holds no inspector state, so suspension does not own or resume a session.

`src/core/inspector.ts` defines commands and events. The content script validates the port and commands. The panel accepts replies from its current port and checks document identity on targets and selected rows. Commands cover start, stop, clear target, mode, navigation, selection, reference inspection, and tracked IDs. Existing scan and highlight requests use the same document element collection.

`ElementCollection` assigns a document-scoped reference ID to a live DOM node. The WeakMap associates the node with its ID and the reverse map uses WeakRef. A distinct row ID identifies the entry in preview and JSON. The model keeps names, selection, ordering, and manual choices when the same reference is rescanned or picked. Replacement nodes get new references. Detached entries remain visible as stale and cannot generate Python while included. A different document starts a new collection when it is scanned or an element is picked. Locators never establish live identity.

Semantic inspection prefers the closest matching interactive or focusable ancestor and resolves labels to their associated control. Exact mode selects the real DOM target. Static targets use the same metadata, candidates, and validation as scanned controls and generate assertion locator attributes. Hierarchy navigation uses the surrounding DOM and returns to the original hovered element.

The overlay uses a fixed, pointer-transparent host with a closed shadow root. It renders patterned borders for hover, navigation, latest and previous selections, and panel highlights. Geometry follows the element's viewport bounding box. For a target inside an open modal or popover, the host moves into that top-layer element. Tooltip text is rendered as text, and metadata captures a bounded allowlist of author attributes. Password and hidden input values, cookies, and browser storage contents are outside metadata extraction.

Pointer events coalesce into one animation-frame update. Changed targets receive a lightweight outline and tooltip immediately. Locator generation waits 160 ms on hover, with fresh evidence at selection. Connected references are checked every 200 ms while active. Stop cancels delayed work, listeners, and overlays. Trusted primary pointer and mouse gestures are intercepted in the capture phase. Earlier window-capture handlers, browser UI, native controls that suppress events, and browser top-layer stacking can limit interception or rendering. Browser-side matching retains its existing approximation limits. Scoped inspection of iframe and shadow-tree internals remains future work.

## Optional Python Playwright validation

The side panel sends versioned JSON to the paired loopback companion. The companion attaches Python Playwright to an operator-approved Chromium debugging port and reuses the connection. It resolves the advertised WebSocket using loopback HTTP without proxies or redirects, verifies its host and port, and uses Playwright's `no_defaults` mode to preserve browser settings such as download behavior. Disconnect drops the driver transport. The externally managed browser remains open. [Architecture decision](decisions/0001-local-playwright-companion.md)

### Protocol and evidence

All operations use POST under `/api/v1`. Requests and responses include `protocol: 1`. The authenticated `status` route exposes versions, connection state, strategy capabilities, and an opaque browser-session ID. `connect` and `disconnect` manage the preconfigured browser. `validate` accepts one to 40 structured candidates, the browser-session ID, a document key, a request ID, a short-lived correlation lease, optional state or trial checks, and a per-candidate timeout from 100 to 3,000 ms. `cancel` references a request ID. Validation is serialized, with a three-second page-correlation budget and a nine-second candidate budget. Successful candidates survive candidate-level failures and timeout in the same batch. Earlier rows survive cancelled or failed subsequent requests unless the application state invalidates the evidence.

The content script marks the document root and intended live node with distinct random temporary attributes. The companion checks eligible top-level Playwright pages for the exact document marker and requires an unambiguous result. It uses Playwright's selector evaluation to count matches and check intended-node membership. Configured test IDs use the real Playwright setter under the validation lock. POM-005 adds bounded chains, containment and text filters, and explicit indexes to the existing CSS and semantic strategies. Arbitrary selector engines, user scripts, and regular expression arguments remain outside the supported contract.

Count, target identity, state, and trial results are separate. States are point-in-time observations. Playwright's visibility query is immediate, and other applicable state queries are bounded by the candidate budget. Hidden or disabled elements can still be correctly matched. Confirmed unique targets may opt into click, hover, or check trials. Trial actions can scroll or affect focus, and cancellation cannot undo such effects. Fill and select have no supported trial in this implementation. Assertion targets can use count and identity regardless of actionability.

Runtime results augment each candidate with a timestamp, duration, request and browser IDs, document/model/candidate IDs, and the applicable test-ID attribute. Browser evidence remains visible. A wrong-target, ambiguous, or no-match runtime result excludes a candidate while current. Confirmed results break score ties, preserving inherent locator priorities. Manual choices are retained, and a conflicting choice blocks generation with an actionable message. Two opt-in policies require a fresh unique result or a confirmed target. The default falls back to browser safeguards when current runtime evidence is unavailable.

The evidence expires after 30 seconds. Navigation, configuration changes, rescan, DOM mutations, and detected connection changes invalidate it. A bounded mutation observer watches for the first relevant change, ignoring extension overlays and validation markers. Connection health is sampled only while current evidence is displayed. Transient markers are removed after completion, cancellation, or a 19-second lease timeout, and on page hide. JSON retains evidence and its freshness without pairing or marker secrets.

### Threat model and limitations

An arbitrary webpage or DNS rebinding attempt must not gain access to a privileged browser session. Bind only to IPv4 loopback, verify exact `Host` and extension `Origin`, and require a constant-time bearer comparison for every operation. The 256-bit pairing secret is generated locally and kept in panel memory and the companion process. The server bounds body size, request threads, candidates, and validation duration. Fixed routes and an explicit locator dispatcher expose no caller-supplied scripts, Python, shell commands, navigation URLs, cookie APIs, browser storage, or filesystem paths. Logs contain route names and outcome codes. Test fixtures and screenshot artifacts are synthetic.

The operating system user, the approved Chrome profile, and the executable serving the configured debugging port are trusted. Other processes with the same local privileges may independently access a debugging port, so keep it private and use an isolated test profile. An application script can see temporary DOM attributes and may react to them. Marker integrity protects against ordinary tab confusion and replacement. It cannot attest to a hostile page intentionally copying markers. State can also change without DOM mutation, for example through stylesheet or control properties, so successful results are observations rather than guarantees. Iframe and shadow-tree target correlation and browser launch ownership are deferred.

## Reusable components

Component models export with `schemaVersion: 2`. Existing flat objects retain their shape and can be generated unversioned or as schema v1. Definitions own relative member candidates, optionality, nested links, user selection, and representative observations. Instances hold their own root locator candidates and optional semantic key. Collections declare an intentional multi-match locator. Model IDs remain stable within the current document. Browser references are opaque document-scoped strings. Loader and reconciliation against saved external page objects remain future work.

Discovery samples up to 800 candidate boundaries, 60 member slots per root, 30 roots per group, and 12 proposals. It compares repeated siblings in the same family and scores structural overlap. It requires a visible interactive member and preserves minor optional variations. Browser matching caches results and semantic indexes per root. A collection locator must match the observed root set exactly. Heading lookup is offered only after verifying distinct keys resolve to their sampled instances.

For each selected member, browser evidence records the count and intended-slot match in each representative root. Optional absence is distinct from a missing required member. Members retain names, choices, selection, and interaction settings when the same slot is rechecked. Moving a flat row into the definition uses its live identity and checks the locator in the new scope. An incompatible choice remains visible until changed. Reconciliation during inspection uses the existing document-scoped identities.

The optional companion evaluates the selected root, parameterized lookups, collections, nested roots, and scoped child locators. Child chains require a unique parent, and a dedicated temporary root marker distinguishes that parent's identity from the child's. Evidence is sampled, timestamped, and archived under the runtime freshness rules. The UI displays collection counts as intentional multiplicity. Scope changes require a new observation or validation. Protocol v1 remains additive. Use companion v0.5.0 with extension v0.5.0 for composed locators. Flat validation continues to use the existing operations.

The generator validates names, graph references, and locator composition before emitting Python. It emits one class per definition, lazy root-bound attributes, optional presence methods, and a small collection API. Separate modules import component dependencies deterministically. ZIP paths derive from sanitized class names. Dynamic or virtualized collections resolve the DOM present at interaction time. Runtime evidence and discovery cover the inspected samples, and future app variants need their own checks. [Component scope decision](decisions/0002-reusable-component-scopes.md)
