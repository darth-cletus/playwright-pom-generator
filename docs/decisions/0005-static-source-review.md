# Analyze source in the local companion and patch approved expression spans

Use Python's AST for language-aware discovery and the tokenizer to identify comments inside candidate edit spans. Track offsets in the UTF-8 source bytes. Keep the original source alongside the AST evidence and splice approved expressions into the original bytes. Whole-file AST printing would rewrite unrelated formatting. Token-only recognition alone would lose Python call and class structure. A concrete syntax tree library could support richer edits, but the current bounded expression replacements can use the standard library. [Python AST](https://docs.python.org/3/library/ast.html), [Python tokenizer](https://docs.python.org/3/library/tokenize.html)

The panel stores caller-selected Python files only in memory. The authenticated protocol v1 service adds source analysis contract 1 and separate analysis and transformation operations. It receives source text and never reads selected paths itself. Transformations reparse the supplied text, check its SHA-256 revision, validate structured locator replacements and return an updated copy and diff. Approvals live in the panel; the service accepts only supported expression IDs from the current parse.

JSON imports use the existing model schemas through v3 and discard live references and runtime evidence. The review report uses schema version 1. Browser evidence and optional Playwright evidence are tied to the active scan. Imported Playwright checks measure cardinality without executing the imported Python or claiming target identity.
